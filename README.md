# ForkBomb

Лабораторная программа: запускает ограниченное число дочерних процессов, считает процессы в ОС и пишет ряд во времени (`process_count.csv`, график `process_count.svg`).

Это исходники. Собранный бинарник в git не входит.

Имя папки историческое. **По умолчанию это не классическая fork-бомба:** потолок `-n` — 32 процесса (`HARD_CAP`), дети живут несколько секунд и завершаются.

## Состав

| Файл | Назначение |
| --- | --- |
| `src/lab_spawn.c` | Запуск детей, подсчёт процессов, CSV и SVG |
| `src/process_count.csv` | Пример ряда с прогона |
| `src/process_count.svg` | Пример графика |
| `Makefile` | Сборка |

Windows: `CreateProcess`, снимок через Toolhelp. POSIX: `fork`, счёт через `/proc`.

## Требования

- `gcc` (MinGW-w64 на Windows или обычный gcc на Linux)

## Сборка

```bat
make
```

Или:

```bat
gcc -Wall -O2 -o src/lab_spawn src/lab_spawn.c
```

## Запуск (безопасный режим)

Из каталога `src` (CSV и SVG пишутся в текущую папку):

```bat
cd src
lab_spawn.exe
```

На Linux: `./lab_spawn`.

Опция `-n N` — сколько детей (0…32). Без аргументов — 16. Дети спят ~4 с и выходят. Сначала ~2 с базовая линия, потом спавн, потом хвост после завершения.

Не оставляйте машину без присмотра, если меняете исходник.

## Режим `-d`

Флаг `-d` включает рекурсивный spawn. В текущем коде глубина **не** останавливает цикл: дочерний процесс крутит бесконечный запуск. Это может завесить систему. **Не запускайте `-d` на рабочей машине и не выкладывайте прогон как «проверку чужого ПК».** Для GitHub и отчёта достаточно режима без `-d`.
