# ForkBomb

Учебная лаба: ограниченный spawn дочерних процессов и запись числа процессов в ОС во времени (`process_count.csv`, график `process_count.svg`).

**Запускайте только в виртуальной машине** или другой одноразовой среде, которую можно выключить. Рабочую систему для прогона не используйте.

Имя папки историческое. **По умолчанию это не классическая fork-бомба.** Без `-d` родитель поднимает не больше `HARD_CAP` детей (32): `-n` обрезается до этого потолка, без аргументов — 16. Дети спят около 4 с и завершаются. `HARD_CAP` ограничивает только этот прямой запуск.

Флаг `-d` с положительным числом включает рекурсивный spawn. В текущем коде глубина не останавливает цикл: дочерний процесс крутит бесконечный запуск. `HARD_CAP` в этом режиме задаёт только длину локального массива pid/handle и число процессов не ограничивает. Такой прогон может завесить систему. Для отчёта и GitHub достаточно режима без `-d`.

## Состав

| Файл | Назначение |
| --- | --- |
| `src/lab_spawn.c` | Запуск детей, подсчёт процессов, CSV и SVG |
| `src/process_count.csv` | Пример ряда с прогона |
| `src/process_count.svg` | Пример графика |
| `Makefile` | Сборка |

Windows: `CreateProcess`, снимок через Toolhelp. POSIX: `fork`, счёт через `/proc`. В ряд попадает число процессов в ОС, не только дети этой программы.

В дереве уже лежит собранный `src/lab_spawn.exe` и файлы сборки (`.obj`, `.ilk`, `.pdb`). Отдельного `.gitignore` нет. Поведение лабы смотрите по исходнику.

## Требования

- `gcc` (MinGW-w64 на Windows или обычный gcc на Linux)

## Сборка

```bat
make
```

Или:

```bat
gcc -Wall -O2 -o src/lab_spawn src/lab_spawn.c
```

## Запуск (безопасный режим)

Только в ВМ. Из каталога `src` (CSV и SVG пишутся в текущую папку):

```bat
cd src
lab_spawn.exe
```

На Linux: `./lab_spawn`.

Опция `-n N` — сколько детей (0…32, дальше режет `HARD_CAP`). Без аргументов — 16. Дети спят ~4 с и выходят. Сначала ~2 с базовая линия, потом спавн и опрос, пока дети живы, потом ~2 с хвост после завершения.

Если правите исходник, оставляйте тот же потолок и не уходите от машины.

## Режим `-d`

`-d` берёт следующее число. Если оно больше нуля, вместо обычных детей запускается рекурсивный режим. Переданная глубина в цикле не проверяется, выхода из него в коде нет. **Не запускайте `-d` даже в ВМ без необходимости и не выкладывайте прогон как «проверку чужого ПК».**

## Что не выкладывать

- `*.exe`, объектники, `.ilk`, `.pdb`
- `.vscode/`

`.gitignore` этих файлов не отсекает: файла в репозитории нет, часть артефактов сборки уже в дереве. Для разбора лабы достаточно исходника, `Makefile` и примера ряда с графиком.
